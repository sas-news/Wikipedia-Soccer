# Draft: 目標ページランダム機能強化計画

## 要件（確認済み）
- 現在の個別指定に加え、難易度ごとのランダム記事選択機能を追加
- 完全ランダムだと到達不可能・不公平なため、難易度調整が必要
- プリセット難易度 + カスタム高度設定の両方を実装予定
- 単語ベクトル、被リンク数、プレビュー数、親カテゴリの一致・近さなどを要素に含める

## 調査結果（Wikipedia API）

### 利用可能なAPIエンドポイント
1. **ランダムページ選択**: `action=query&list=random`
   - rnnamespace(0=記事), rnlimit(max 500), rnminsize, rnmaxsize
   - 注意: 固定シーケンスの中からランダム開始点を選ぶ仕組み

2. **ページメタデータ**: `action=query&prop=info|categories|links`
   - ページサイズ、カテゴリ一覧、 outgoing links

3. **被リンク（backlinks）**: `action=query&list=backlinks`
   - ページへのリンク数（人気度・中心性の指標）

4. **ページビュー**: Wikimedia REST API
   - `metrics/pageviews/per-article/{project}/all-access/all-agents/{title}/daily/{start}/{end}`
   - 最大30日間ずつ。人気度・到達可能性の指標

5. **カテゴリ構造**: `action=query&list=categorymembers`
   - 親カテゴリの取得は可能だが、再帰的な木構造の走査は手動
   - deepcat: 検索演算子で深いカテゴリ検索が可能

6. **拡張統計（XTools）**:
   - links_in, links_out, redirects
   - prose（文字数）

### 難易度指標の候補
- **到達可能性**: 被リンク数、ページビュー数（多いほど中心性が高く到達しやすい）
- **複雑さ**: ページサイズ、リンク密度、セクション数
- **カテゴリ距離**: 親カテゴリの一致度・階層距離
- **意味的距離**: Wikipedia2Vec埋め込みのコサイン類似度
- **可読性**: readability.toolforge.org（多言語対応）

## 技術的決定事項（ユーザー確認済み）
- **対象言語**: 日本語Wikipediaのみ
- **スキル調整**: まずは静的プリセット（初級・中級・上級など）で運用し、将来的にプレイ履歴による動的調整を追加
- **難易度定義**: 到達可能性（中心性）を重視。被リンク数、ページビューなどでページの「中心性」を測定
- **スタートページ**: 完全ランダム（Hubページ依存を避けるため）
- **目標ページ**: 難易度に応じたランダム選択
- **カスタム設定**: 詳細な数値入力。各指標の閾値や重み付けを具体的な数値で入力可能
- **アーキテクチャ**: ハイブリッド。サーバーで難易度データベースを構築・更新し、クライアントはそれを参照。重い計算はサーバー、軽いフィルタはクライアント
- **APIレート制限**: 厳しくないが、User-Agent必須。キャッシュが重要
- **バッチ処理**: titles=PageA|PageB|PageC で複数ページを一括取得可能
- **埋め込みモデル**: Wikipedia2Vec（日本語対応要確認。12言語対応とあるが、日本語が含まれているか要確認）
